1. 系统概述

NDM 是一套网络设备配置收集与分析系统，支持通过 SSH 登录 Cisco IOS 交换机/路由器和 Aruba OS 交换机， 自动采集 running-config、startup-config、接口状态、路由表、系统日志等关键配置数据，保存到本地进行版本管理和分析。

核心功能

  • 设备发现：通过 Ping / TCP 检测设备在线状态
  • 配置采集：SSH 登录设备，自动下载配置文件（10-30 秒）
  • 路由器支持：Cisco IOS 路由器专用解析，自动收集路由表（show ip route）
  • 设备类型自动探测：配置类型不正确时自动尝试正确驱动
  • 配置分析：完整性验证、接口状态分析、利用率统计、变更检测
  • 前面板可视化：交换机端口状态面板 + 路由器接口层级树
  • 版本管理：按周归档，保留最近 10 周历史配置
  • 配置对比：左右分栏对比两个版本差异，高亮变化
  • 批量采集：多选设备统一采集，实时查看进度
  • 双语文案：中文 / 英文界面一键切换

技术架构

前端：React 18 + TypeScript + MUI v5 (OLED Dark 主题)
后端：Python FastAPI + Netmiko (SSH)
存储：本地 YAML 配置文件 + 文件系统按周归档

登 录

1
健康检查：页面加载时自动检测后端服务状态。绿色圆点 + "系统运行正常"表示后端在线； 红色圆点 + "后端服务不可用"表示无法连接；加载中转圈表示检测中。

安全说明

  • 用户名和密码使用 Base64 + encodeURIComponent 编码后存储
  • 仅在当前浏览器标签页有效（sessionStorage），关闭标签页即清除
  • 4 小时后凭据自动过期，需重新登录
  • 密码支持所有特殊字符（!@#$%^&*()=+?<> 等）

4.1 按 Location 筛选设备卡片

  1. 点击顶部 Location 按钮（如 BJQ），该按钮高亮为绿色
  2. 下方卡片区域自动显示该 Location 下的所有设备
  3. 每张设备卡片包含：设备名、IP、类型、位置、备注、采集按钮
  4. 再次点击同一按钮取消筛选，恢复全部设备视图

4.2 单台设备采集配置

1
在设备卡片或表格中，点击 ☁ Collect 按钮
2
系统先 Ping 设备检查可达性（黄色进度提示）
3
Ping 成功后自动进入 SSH 采集阶段（蓝色进度提示）
4
采集完成后弹出结果对话框，显示设备名、IP、软件版本、序列号、Running Config 行数

类型自动修正

如果配置的设备类型不正确（如将 Aruba CX 6300 配置为 aruba_osswitch），系统会自动探测正确的驱动类型。 采集成功后弹出黄色警告提示用户类型已自动修正。建议之后在设备编辑中更新类型配置。

4.4 添加 / 编辑 / 删除设备

点击页面右上角 Add Device 按钮，弹出添加设备表单：

  • Name：设备名称（字母、数字、下划线、连字符）
  • IP Address：管理 IP 地址
  • Type：选择设备类型（见下表）
  • Platform：平台/型号（可选，如 aruba_6300，随 Type 动态联动）
  • Location：机房位置（可选，用于 Location 筛选）
  • Notes：备注信息（可选）

6.1 单版本查看（Single 模式）

  1. 点击 Location 按钮筛选（可选），从下拉框选择目标设备
  2. 选择 周目录（如 2026-19），系统加载该周的配置文件列表
  3. 选择具体文件，内容自动加载
  4. 三个 Tab 切换查看方式：
    • Raw — 原始文本，终端风格等宽字体显示
    • Formatted — JSON 格式化（validation.json、performance.json 等）
    • Analysis — 智能解析：Config Validation 错误表格 / Performance 接口状态 / Change Detection 变更统计

8. 多语言切换

系统支持中文 / 英文两种界面语言，在 Dashboard 和 Devices 页面顶部有语言切换按钮。

Language: 中文 English

切换后即时生效，无需刷新页面。包括：导航、按钮、提示信息、表格表头、错误消息等。

  • 翻译文件位于 frontend/src/i18n/zh.ts 和 frontend/src/i18n/en.ts
  • 使用 React Context 实现，切换即时生效

9. 常见问题

Q: 点击 Collect 后报错 "Pattern not detected"？

A: 设备类型与驱动不匹配。系统已内置设备类型自动探测功能，连接失败时会自动尝试其他驱动。如果仍然失败，请检查设备 type 和 platform 字段是否正确。Aruba CX 系列（6300/6400/8320 等）需使用 aruba_aoscx。

Q: 密码包含特殊字符（=、?、@ 等），会影响登录吗？

A: 不会。系统已处理所有特殊字符的编解码。密码在前端使用 base64 + encodeURIComponent 编码存储，传输时通过 FormData 发送，后端通过 FastAPI Form 解析 — 全程不会截断或篡改。

Q: 设备显示 Offline，但能 SSH 登录？

A: Ping 使用的是 ICMP 协议，部分网络环境会禁止 ICMP。系统在 Ping 失败后会自动尝试 TCP 22 端口连接。如果 TCP 22 开放，仍会标记为 Online。如果仍显示 Offline，请检查后端服务器是否能访问设备 IP。

Q: 批量采集时某台设备一直停在 "pending" 状态？

A: 批量采集是串行处理的，每台设备需要 10-30 秒。请等待当前设备完成后，下一台才会开始。可以在表格右侧状态列查看实时进度。

Q: 配置对比时两边内容完全一样？

A: 请确认选择的两个周目录不同。如果两周之间配置没有变化，两边内容相同是正常的 — 说明设备配置在此期间未发生变更。

Q: 路由器类型如何配置？

A: 添加设备时，Type 选择 cisco_ios_router。系统将自动：收集路由表（show ip route）、按 5 列格式解析接口状态、展示接口层级树（含子接口缩进）、不跳过 Loopback 接口。

Q: 中文界面如何切换为英文？

A: 在 Dashboard 或 Devices 页面顶部找到语言切换按钮，点击 English 即可切换。系统会记住选择，刷新后保持。
