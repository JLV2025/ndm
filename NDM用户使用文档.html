PART I — ENGLISH

1. Introduction

NDM (Network Device Management) is a network device configuration collection and analysis system. It connects to Cisco IOS / IOS XE / Router and Aruba OS / CX switches over SSH, collects running-config, logs, interface status, routing tables and version information, stores everything in SQLite, and provides a web console for viewing, diffing, analyzing, and AI-assisted log diagnosis.

Key Features

  • Multi-vendor — Cisco IOS, Cisco IOS XE, Cisco IOS Router, Aruba OS, Aruba OS CX
  • Web console — React + MUI OLED Dark theme, built for network operations
  • Device management — add / edit / delete / CSV batch import, filter by type and location
  • One-click collection — running-config, logs, interface status, routing table, version info
  • AI log analysis — bring-your-own LLM API key (DeepSeek / Qwen), priority-chain fallback, local caching, auto-masking
  • Online viewer — syntax-highlighted configs, version diff
  • Alerts & reports — port DOWN / config change / version mismatch detection with fix suggestions
  • Dashboard charts — device-type donut, port-status bar, traffic Top 10, config-change trend + heatmap
  • Front panel — switch port-status panel + router interface tree, stacking support, 10Gb red badges
  • Port topology — CDP/LLDP + ConfigParser merged, React Flow canvas, 4-layer auto layout, stacking, LAG aggregation
  • Network topology — CDP + LLDP auto discovery, 3-layer layout (WAN → Core → Access), PNG / Visio export
  • SQLite storage — running-config dual-track (file + DB), logs de-duplicated by timestamp
  • Bilingual UI — Chinese / English switch at one click

2. Quick Start

2.1 Requirements

  • Python 3.9+
  • Node.js 18+
  • SSH-reachable target network devices

2.2 Installation

1
Create a Python virtual environment: python3 -m venv venv
2
Activate it (Windows PowerShell: .\venv\Scripts\Activate.ps1)
3
Install backend dependencies: pip install -r backend/requirements.txt
4
Install frontend dependencies: cd frontend && npm install && cd ..

2.3 Start

Development Mode

Terminal 1: python backend/main.py (backend on port 8002)
Terminal 2: cd frontend && npm run dev (frontend on port 3000, proxies /api to backend)
Open http://localhost:3000.

Production Mode

Build the frontend (cd frontend && npm run build && cd ..), then run python backend/main.py. FastAPI serves the static files directly — everything on one port. Open http://localhost:8002.

On Windows you can simply double-click start.bat.

3. Login & Session

The login page manages the SSH credentials used to collect device data, and performs a health check of the backend at the same time.

1
Health check — on page load the backend status is probed. A green dot with "System Running Normally" means online; a red dot means the backend is unreachable.
2
Enter credentials — the SSH username and password used to log into network devices.
3
Sign in — credentials are encoded and kept in browser sessionStorage, valid for 4 hours.

Security Notes

  • Credentials are stored Base64 + encodeURIComponent encoded in sessionStorage
  • Valid only in the current browser tab; cleared when the tab is closed
  • Credentials expire automatically after 4 hours — sign in again
  • All special characters are supported (!@#$%^&*()=+?<>, etc.)

5. Device Management

This is the core page: device filtering, collection, management, and batch operations.

5.1 Filter by Location

Click a Location chip (e.g. BJQ) to show only devices in that location; click again to clear the filter.

5.2 Collect a Single Device

1
Click the Collect (☁) button on a device card or table row
2
The system pings the device to check reachability (yellow progress)
3
On success, SSH collection starts automatically (blue progress)
4
A result dialog shows device name, IP, software version, serial number, and running-config line count

Automatic Type Correction

If the configured device type is wrong (e.g. an Aruba CX 6300 configured as aruba_osswitch), the system probes and detects the correct driver automatically, then shows a yellow warning suggesting you update the type in the device settings.

5.3 Batch Collection

  • Select all — checkbox in the table header
  • Multi-select — check target devices; a Batch Collect (N) button appears in the toolbar
  • Progress — overall progress bar on top; each row updates live; results are summarized with success/failure chips

5.4 Add / Edit / Delete Device

  • Add — click Add Device; fields: Name, IP Address, Type, Platform (optional, linked to Type), Location (optional), Notes (optional)
  • Edit — click the ↻ icon in the row
  • Delete — click the ✕ icon, confirm in the dialog

5.5 CSV Batch Import

In the device list, use the import dialog to upload a CSV file (download the provided template first). The backend validates and imports devices in bulk.

8. Alerts

The Alerts page lists anomalies detected after each collection. Each alert has a type, severity, title, detail, and a generated fix suggestion.

10. Log Analyzer & AI Diagnosis

Browse device logs by week and severity, then run AI analysis on selected entries.

10.1 Browsing Logs

  • Tree view: Device → Severity → Log entries, logs load on demand
  • Severity levels 0–7 follow the standard Syslog ladder (Emergency → Debug), color-coded
  • Filter by week if needed

10.2 AI Analysis

  1. Select a device, check the target log entries, click AI Analyze
  2. The first time you use it, configure the LLM API Key in the settings dialog (⚙)
  3. Multiple LLM providers form a priority chain — if the first fails, the next provider is tried automatically
  4. Results are cached locally; the same error pattern hits the cache instantly next time
  5. Before sending, the request is auto-masked (device names / IPs replaced with placeholders); replies are de-masked afterward

Configured Providers

  • DeepSeek — https://api.deepseek.com/v1, model deepseek-chat
  • Qwen — https://dashscope.aliyuncs.com/compatible-mode/v1, model qwen-turbo

API keys can be left empty in config/settings.yaml and filled in from the web settings dialog.

11. Network Topology

Multi-device topology per location, built from CDP + LLDP neighbor discovery plus ConfigParser port descriptions.

  • 3-layer layout — WAN → Core → Access; intelligent shortest-path wiring
  • Port DOWN warning — ports with neighbor entries but physically down show a red ✕
  • Links are kept — even when a device is offline/failed, the link remains visible
  • Export — PNG image or Visio (.vsdx) export

12. Port Topology

Single-device port connection map, merging CDP/LLDP neighbors and ConfigParser (port descriptions).

  • 4-layer auto layout — WAN → Core → Access → Endpoints
  • Stacking — stack members expanded as separate groups
  • Endpoint aggregation — endpoints aggregated with counts (e.g. AP ×N)
  • LAG / Port-Channel — logical aggregation, physical members hidden
  • Port DOWN red ✕ — neighbor entry exists but the port is physically down
  • Pipeline-style rounded edges, auto-centering and fit-to-view
  • AP detection — CDP/LLDP-discovered APs marked as endpoint aggregates

13. Data Storage

All collected data is stored in SQLite (data/ndm.db); only running-config keeps a file copy for emergency recovery.

data/
├── ndm.db                    # SQLite database (primary store)
├── YYYY-WW/                  # weekly archive directory
│   └── {device-name}/
│       └── running-config.raw   # dual-track copy (only file kept)
└── {device-name}/            # legacy layout (backward compatible)
    └── YYYY-WW/
  • Up to 10 weekly versions retained per device; older weeks auto-cleaned
  • Logs are de-duplicated by timestamp

14. FAQ

Q: The login page shows "Backend service unavailable"

Make sure the backend is running (python backend/main.py) and port 8002 is reachable.

Q: Collection failed

Check SSH reachability, username/password, and that the device type is correct. If the type is wrong, the system auto-probes the right driver and warns you to update it.

Q: Password contains special characters

All special characters are supported. If you still fail to log in, try re-entering the credentials in the login page.

Q: "Session expired" — I have to sign in again

SSH credentials are kept for 4 hours in sessionStorage. Re-enter them on the login page.

Q: Where is the API documentation?

Start the backend and open http://localhost:8002/docs (Swagger UI).

15. 系统介绍

NDM（网络设备配置管理系统）是一套网络设备配置采集与分析系统，通过 SSH 登录 Cisco IOS / IOS XE / 路由器和 Aruba OS / CX 交换机， 自动采集 running-config、日志、接口状态、路由表和版本信息，统一存入 SQLite 数据库， 并提供 Web 控制台进行查看、对比、分析和 AI 日志诊断。

核心功能

  • 多厂商支持 — Cisco IOS、Cisco IOS XE、Cisco IOS Router、Aruba OS、Aruba OS CX
  • Web 管理面板 — React + MUI OLED Dark 主题，专为网络运维设计
  • 设备管理 — 添加、编辑、删除、CSV 批量导入，按类型 / 位置筛选
  • 一键采集 — running-config、日志、接口状态、路由表、版本信息
  • AI 日志分析 — 自配 LLM API Key（DeepSeek / Qwen），优先级链降级，本地缓存，自动脱敏
  • 在线查看 — 配置代码高亮查看，双版本对比（diff）
  • 告警与报表 — 端口 DOWN / 配置变更 / 版本不一致等异常检测，自动生成修复建议
  • Dashboard 图表 — 设备类型环形图、端口状态柱状图、流量 Top 10、配置变更趋势 + 热力图
  • 前面板可视化 — 交换机端口状态面板 + 路由器接口层级树，支持堆叠、10Gb 红色数字标识
  • 端口拓扑图 — CDP/LLDP + ConfigParser 双数据源，React Flow 画布，四层自动布局，堆叠展开，LAG 聚合
  • 网络拓扑图 — CDP + LLDP 邻居自动发现，三层分层布局（WAN → 核心 → 接入），PNG / Visio 导出
  • SQLite 全量存储 — running-config 双轨（文件 + 库），日志按时间戳去重
  • 双语文案 — 中文 / 英文一键切换

17. 登录与会话

登录页面用于管理采集设备所用的 SSH 凭据，同时会执行一次后端健康检查。

1
健康检查 — 页面加载时自动检测后端状态。绿色圆点 + “系统运行正常”表示在线；红色圆点表示后端不可用。
2
输入凭据 — 登录网络设备所用的 SSH 用户名和密码。
3
登录 — 凭据经编码后保存在浏览器 sessionStorage 中，有效期 4 小时。

安全说明

  • 凭据以 Base64 + encodeURIComponent 编码后存储在 sessionStorage
  • 仅在当前浏览器标签页有效，关闭标签页即清除
  • 4 小时后凭据自动过期，需重新登录
  • 支持所有特殊字符（!@#$%^&*()=+?<> 等）

24. 日志分析与 AI 诊断

按周和严重级别浏览设备日志，并支持对选中的日志条目执行 AI 分析。

24.1 浏览日志

  • 树形视图：设备 → 严重级别 → 日志条目，日志按需加载
  • 严重级别 0–7 遵循标准 Syslog 分级（Emergency → Debug），颜色区分
  • 可按周过滤

24.2 AI 分析

  1. 选择设备，勾选目标日志条目，点击 AI 分析
  2. 首次使用需在设置对话框（⚙）中配置 LLM API Key

  4. 分析结果本地缓存，同类型错误下次秒级命中
  5. 发送前自动脱敏（设备名 / IP 替换为占位符），回复后再还原

27. 数据存储

所有采集数据统一存入 SQLite（data/ndm.db），仅 running-config 保留文件副本供紧急恢复。

data/
├── ndm.db                    # SQLite 数据库（所有数据主存储）
├── YYYY-WW/                  # 周归档目录
│   └── {设备名称}/
│       └── running-config.raw   # 双轨保留（唯一文件）
└── {设备名称}/               # 旧版数据目录（向后兼容）
    └── YYYY-WW/
  • 每设备最多保留 10 个周版本，更早的自动清理
  • 日志按时间戳自动去重

28. 常见问题

问：登录页显示“后端服务不可用”

请确认后端已启动（python backend/main.py）且端口 8002 可访问。

问：采集失败

检查 SSH 可达性、用户名密码、设备类型是否正确。类型错误时系统会自动探测正确驱动并提示更新。

问：密码包含特殊字符

支持所有特殊字符。若仍登录失败，请在登录页重新输入凭据。

问：“会话过期”，需要重新登录

SSH 凭据在 sessionStorage 中保存 4 小时，过期后在登录页重新输入即可。

问：API 文档在哪里？

启动后端后访问 http://localhost:8002/docs（Swagger UI）。
